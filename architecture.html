02 Two planes — the core design choice

CLAI splits exploration from harness intelligence. This is architecture, not a two-panel UI — the operator still sees one Pi/OpenCode-like terminal pane.

Tool plane

  • grep / glob / read / edit / write — live repo access
  • bash · bash_bg* · parallel — real execution
  • LSP — defs, refs, diagnostics
  • repo_intake — repo map JSON seed
  • task · explore (read-only) / general (+bash)

Not its job: global AST index, vector search, replacing memory.

Harness plane

  • Memory tiers — task · convention · evidence · preference
  • ContextManager — token budget · staleness · ablations
  • compactHistory — deterministic digest, no extra model call
  • Verification — evidence + repair loop (scaffold)
  • Trace — what happened, append-only JSONL

Not its job: replace grep/LSP for discovery.

Rule: exploratory discovery is never “search the memory table.” Memory cites paths; tools read the live repo.

03 Run lifecycle

One interactive session, traced end to end. “What runs today vs designed” is a first-class status in CLAI.

  1. clai / clai run "fix the test" — operator starts a session; UiBus emits run_start into the trace.
    wired
  2. ensureIntake — repo_intake runs once per session; product one-liner appended to system context.
    wired
  3. compactHistory — if estimated tokens exceed ~45k, older turns collapse into a deterministic digest (keeps original task + last N messages).
    wired
  4. Agent loop — up to maxSteps (default 12) of generateText + tools against the provider, with 429/5xx retry + jitter and one-shot tool-arg repair.
    wired
  5. Tool calls — direct (grep · parallel · read · edit · bash · bash_bg · LSP) or delegated via task subagents (explore read-only / general +bash, ~10 steps, bounded summary). Multiple calls parallelize in one step.
    wired
  6. Trace — every model_step, tool_call/tool_result, approval, and error appended to .clai/traces/<runId>/events.jsonl.
    wired
  7. Verification gate — designed: PASS | FAIL | BLOCKED + evidence. Today: soft stop on model finish (verify/ exports empty).
    scaffold
  8. run_end — status ok/fail; footer shows trace path.
    wired

05 Storage boundaries — no dual-write

Each store owns one concern. Working memory (current file, last grep) lives in the JSONL / in-process state — never in SQLite. Reserved tiers episodic, procedure, working exist in types but are not writable: they belong in session JSONL.

StoreOwnsMutability
JSONL traceMessages, tool calls, approvals, costs, full truncated tool outputAppend-only
Bench historyRun records, aggregates, per-task metricsAppend-only
Memory DBConventions, evidence, task notesInvalidate / supersede
assemble()Prompt context for one model turnEphemeral
compactHistory()Compressed middle of message listEphemeral

06 Context & memory

Two complementary mechanisms: history compaction (wired in the main loop) and memory assembly (built, demo-wired).

compactHistory() wired

  • Keeps original task + last N messages verbatim (CLAI_COMPACT_KEEP_TURNS, default 10)
  • Tool call/result pairs → one-line outcomes
  • Superseded reads of the same path dropped
  • Files touched by edit/write listed
  • No extra model call — deterministic digest

Triggers at ~45k estimated tokens (CLAI_COMPACT_THRESHOLD_TOKENS).

ContextManager.assemble() demo-wired

  • Real ablation gates — memoryEnabled, structuralCitationsEnabled
  • Hash cite_path → invalidate stale rows at assemble time
  • Priority: evidence → convention → task, then fill token budget
  • Labels UNTRUSTED_DATA vs TRUSTED_MEMORY — injection resistance
  • Emits context_stage into the run trace (glass pane)

Demo: clai demo injection against fixtures/red-team-readme/.

conventionYesdurable

07 Sandbox & approvals

src/sandbox/index.ts wraps @anthropic-ai/sandbox-runtime with a structured stub fallback. Deny-by-default unless CLAI_AUTO_APPROVE=1.

ModeWhenBehavior
runtimeNative sandbox initializeswrapWithSandbox() + scrubbed env
stubWindows ARM, missing binary, init timeoutScrubbed env + approval hooks still apply

Approval kinds

  • egress — curl, wget, npm publish…
  • destructive — rm -rf, format, dd…
  • out_of_repo — cwd outside workspace root

Env scrub

Removes *_API_KEY, *_TOKEN, *_SECRET and similar before any shell execution. .env / .env.local are deny-write in runtime filesystem policy.

08 Trace & glass pane

Append-only JSONL at .clai/traces/<runId>/events.jsonl — a judge-grade audit of what happened. Every run gets an 8-char UUID prefix; bench tasks write per-task traces under temp workspaces.

EventPayload
run_start / run_endcwd · timestamp / status (ok|fail)
model_stepprovider, finishReason, toolCalls, usage
assistant_textmodel prose (truncated at 4k chars)
tool_call / tool_resulttool name, target, duration; full output when capped
tool_repairschema repair attempts
approvalgate decisions
error / infofailures + recovery / compaction, provider_retry, subagent scope
context_stageContextManager.assemble() stage start/complete

clai glass — parallel observability

A second terminal process that tails the active (or pinned) run's events.jsonl and renders the Context Manager pipeline stage-by-stage. Read-only consumer; does not modify UiBus or the main Ink ADE. --follow-latest (default) / --run <runId> to pin & replay.

09 Verification — the biggest delta vs OpenCode

OpenCode treats a model stop finish reason as done; tests are advisory. CLAI's design contract is done means evidence: PASS | FAIL | BLOCKED + a repair loop.

CLAI (designed)

  • Terminal states PASS / FAIL / BLOCKED
  • Evidence-driven repair loop before declaring done
  • Verify seam scaffolded at src/verify/index.ts
  • Bench checkers (check.mjs) already encode this contract per task

Today (honest status)

  • Loop uses soft completion on model finish
  • verify/ exports are empty — scaffold only
  • Intake, compaction, retry, repair, subagents all wired today

Status chips throughout this page mark wired vs scaffold honestly.
