01 · The difference

Not a chatbot. Not a script.
A harness.

Generic AI chat knows nothing about your repo. DIY agent scripts reinvent grep. CLAI is the middle path — built around the same primitives your editor already uses.

CLAI harness
  • ✓Workspace-native — reads your repo, not your clipboard
  • ✓Editor-grade tools — grep, glob, read, edit, write, bash, LSP
  • ✓Budgeted context — never blows the window
  • ✓Sandboxed bash — approval hooks + env scrub
  • ✓Append-only traces — every token, tool call, and cost
  • ✓Provider-agnostic — swap with one env var
  • ✓Headless-ready — CI pipes, CLAI_NO_TUI=1
  • ✓Benchmarks — offline, reproducible, live dashboard
AI chat browser tab
  • ✕Blind to your repo — you paste, it guesses
  • ~Copy-paste loop — code out, code back, forever
  • ✕No real file system, shell, or LSP access
  • ✕Context reset every conversation
  • ✕No audit trail of what it actually did
  • ~Locked to one vendor's UI & model
  • ✕Useless in CI
  • ✕No metrics — just vibes
DIY scripts homegrown
  • ✓Does touch the workspace
  • ~Reimplements grep + glob + edit… badly
  • ~Prompt stuffing, no context discipline
  • ✕Shell runs with no guardrails
  • ✕Logs are an afterthought, if they exist
  • ✕Hardwired to one provider SDK
  • ✕TTY-only, fragile in CI
  • ✕You benchmark by squinting
02 · Capabilities

Everything an agent needs.
Nothing it doesn't.

🧰

Native toolchain

grep, glob, read, edit, write, bash, LSP (definitions, references, diagnostics) and repo intake — the same primitives your editor uses. Read-only tools fan out in parallel.

src/tools/
🛡️

Sandboxed execution

Shell work runs through an Anthropic sandbox-runtime wrapper with env scrubbing and approval hooks. No sandbox binary? A structured stub keeps demos and help working everywhere.

src/sandbox/
🧠

Persistent memory

SQLite-backed memory with a full CLI — memory list | get | set | delete | export. What the agent learns survives across sessions, not just one prompt.

src/memory/
📐

Budgeted context

Context is assembled on a budget with ablation gates — the harness decides what actually earns its tokens, so you don't blow the window mid-task.

src/context/
🪵

Full traces

Append-only JSONL per run under .clai/traces/<runId>/events.jsonl. Every tool call, I/O, token and cost — replayable, auditable, honest.

src/trace/
🖥️

Terminal-native UI

An Ink ADE shell — header, activity column, context strip, footer — driven by a UiBus event API. Flip CLAI_NO_TUI=1 and the same events stream headless to CI.

src/ui/
⚡

Lightweight by design

Heavy natives are lazy-imported so clai --help stays instant. Node ≥ 20, one package, one binary, zero framework lock-in.

bin/clai.js
🧪

Offline demos

No API key? pnpm clai demo runs an offline edit + bash happy path; demo lsp exercises intake and TypeScript diagnostics on fixtures.

fixtures/
03 · Providers

Bring your own brain.

Built on the Vercel AI SDK with a pluggable provider registry — swap models with one environment variable, no loop changes.

cerebras ✦ default groq openrouter openai anthropic gemini deepseek gateway
CLAI_PROVIDER=deepseek CLAI_MODEL=deepseek-v4-flash — done. Add a provider in src/adapter/providers.ts, never touch the loop.

📊 Bench it. Prove it.

No more "trust me, it works". pnpm clai bench run --offline pushes parallel task subsets through the harness, and bench serve renders a live metrics dashboard on port 4310 — tasks, tokens, cost, and pass rates over history.

05 · Quick start

Up and running in 30 seconds.

# install & configure
$ pnpm install
$ cp .env.example .env      # add your provider key (e.g. GROQ_API_KEY)

# try it offline — no API key needed
$ pnpm clai demo
$ pnpm clai demo lsp

# let it loose on a repo
$ pnpm clai run "what's in the codebase?" --cwd fixtures/tiny-edit

# see everything it did — tools, I/O, tokens, cost
$ pnpm clai chat

# measure it
$ pnpm clai bench run --offline --serve
